ANDROID APP · UI 设计稿 v1.0

CoCo Music — 音乐搜索与下载客户端

面向 m.resound.vip 的原生 Android 客户端设计稿。5 个功能模块、4 个底部导航 + 全屏播放页、深色主题优先。本稿为开发前的视觉与交互定稿依据。

Kotlin + Compose Material 3 minSdk 24 / target 34 深色优先 · 浅色跟随系统 Media3 · Room · WorkManager
01

深色为主基调（音乐场景沉浸感），单一强调色 #E5484D 只用于「正在发生的事」——当前播放、下载中、已选中。琥珀色仅作语义辅助（音质档位 / 警告），不承担品牌表达。

交互状态清单

每个页面必须实现的全部状态。留白即 bug——开发时不留"到时候再定"的空位。

页面状态呈现方式
搜索首次进入空态 + 热门歌手快捷入口（周杰伦 / 孙燕姿 / 林俊杰 / 陈奕迅）+ 「已选渠道健康速览」卡片
搜索加载中每渠道独立骨架屏，不做整页转圈——快的渠道先出结果，慢的渠道后补
搜索渠道无结果渠道分组下显示「该渠道无结果」灰字，不隐藏分组（用户要看到渠道确实响应了）
搜索渠道回落到 netease渠道名后加黄色 ⚠ 徽标「已回落」，点击说明原因
搜索全部渠道失败空态 + 「重试」按钮 + 展示各渠道具体错误（500 / 超时 / 空）
搜索网络断开顶部横幅「网络不可用」，保留上次结果不清空
播放取流失败保留封面与歌名，居中显示「解析失败，换渠道试试」+ 渠道切换按钮
播放歌词缺失歌词区显示「暂无歌词」，不空白
收藏夹无歌单空态插画 + 「新建歌单」CTA
歌单详情空歌单空态 + 「去搜索添加」
下载队列空空态 + 「去搜索」
下载下载中进度条 + 实时速度 + 剩余时间；可暂停/取消
下载直链 403 过期自动重取直链并 Range 续传，UI 显示「链接已过期，正在恢复」
下载失败红色进度条 + 原因（取流失败 / 直链失效 / 存储空间不足 / 仅 WiFi）+ 重试 / 换渠道
下载存储空间不足下载前预检可用空间，不足时提前拦截并提示
全局下载中切后台前台服务保持下载，通知栏可暂停/取消
全局未授予通知权限首次下载前引导授权（Android 13+ 运行时权限）
05

关键设计决策

以下 6 条是这份设计稿与常见做法不同的地方，都是为真实 API 约束做的适配。

01
渠道 chip 带健康指示点

线上 17 个渠道实测只有 5 个当前可用，且随时可能变化。健康点直接来自「渠道体检」缓存，让用户在搜索前就知道哪些渠道能用，而不是搜完发现全是空。

02
每条结果都显示来源渠道徽标

同一首歌在不同渠道的音质、时长、版本都不同（实测云音乐给 FLAC、米兔给 MP3）。徽标让用户知道自己在比什么，避免「收藏了 3 个版本」这种重复收藏。

03
音质徽标只显示真实格式与位率

线上 netease 的 hires / sky / jymaster 四档实测全部返回同一个 2000k FLAC。徽标按实测值显示（如 FLAC 2000k），不标「超清母带」误导用户。

04
「已回落」徽标必须显式提示

线上对未知渠道会静默回落到 netease。若 APP 不做比对，用户搜 QQ 音乐却拿到网易结果且毫无察觉。所以每个渠道分组都校验返回项的 provider 字段，不一致就打黄色徽标。

05
底栏 4 项而非 5 项

播放不是「一个页面」，而是一个持续状态。把它做成底栏第 5 项会诱导用户期待每次都从这里进入。改为 Mini Player 常驻 + 点击唤起全屏页，符合 Android 音乐类应用惯例。

06
歌单卡片用前 4 首封面拼贴

自建收藏夹的可辨识度主要来自封面。但下载后才有本地封面，未下载时用 API 封面色块占位，保证视觉一致不塌陷。

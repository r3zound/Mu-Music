### 关于分类的实现方式（重要）

音源站 `m.resound.vip` **只有 4 个接口**，其中没有任何榜单 / 歌单 / 分类接口
（上游 `markcxx/coco-downloader` 本身就是纯搜索下载器）。
所以每个分类本质上是「**关键词 × 渠道组合**」的搜索预设：

| 分类 | 关键词（重复点击自动轮换） | 参与渠道 |
|---|---|---|
| 排行榜 | 热歌榜 → 飙升榜 → 热歌推荐 | netease/qq/kugou/migu |
| 歌单 | 精选歌单 → 歌单合集 → 好听的歌单 | netease/qq/kugou |
| 华语 | 华语热歌 → 华语经典 → 粤语歌 | netease/qq/kugou/migu |
| 情歌 | 情歌 → 情歌推荐 → 想你的歌 | netease/qq/kugou/migu |
| 欧美 | 欧美音乐 → 英文歌 → 欧美流行 | netease/qq/kugou |
| 儿歌 | 儿歌 → 儿童歌曲 → 卡通儿歌 | netease/qq/kugou/migu |
| 经典 | 经典老歌 → 怀旧金曲 → 经典歌曲 | netease/qq/kugou/migu |
| 电音 | 电音 → EDM → 电子音乐 | netease/qq/kugou |
| 说唱 | 说唱 → Rap → 嘻哈 | netease/qq/kugou/migu |
| 慢摇DJ | 慢摇DJ → DJ舞曲 → Deep House | netease/qq/kugou |
| 轻音乐 | 轻音乐 → 纯音乐 → 钢琴曲 | netease/qq/kugou |
| 驾车 | 驾车音乐 → 开车神曲 → 开车DJ | netease/qq/kugou/migu |
| 民谣 | 民谣 → Folk → 吉他弹唱 | netease/qq/kugou |

点分类 → 跳到搜索页，**自动带着该分类的关键词和渠道组合执行搜索**，
复用搜索页已有的渠道筛选 / 分组切换 / 音质选择 / 批量操作，一行 UI 代码都没重复写。

重复点同一个分类，关键词会轮换到下一个（`HomeViewModel.rotation`），避免每次都是同一批歌。

> **结论**：分类是「预设检索」而不是「官方榜单」。这是源的能力边界，换任何客户端都一样。

## 2. 歌手可点击

搜索结果、收藏列表、歌单详情里的**歌手名现在可以点**，点了直接按这个歌手重新搜索。

- 歌手字段形如「周杰伦, 李硕, 张鑫」，取**第一位**作为搜索词（`MusicItem.primaryArtist`）
- 分隔符覆盖 `,` `、` `/` `&` `，`
- 歌手名可点时颜色提亮（ink3 → ink2），给用户暗示

实现：`ui/components/Common.kt` 的 `TrackRow` 新增 `onArtistClick: ((String) -> Unit)?` 参数，
各页把回调接到 `viewModel.searchKeyword(artist)` 或导航到 `search/keyword/{keyword}` 路由。

## 3. 默认收藏

新增内置歌单「**默认收藏**」：

- **首次启动自动创建**（`FavoritesViewModel.init` → `ensureDefaultPlaylist()`）
- **搜索结果每次被点开播放，自动入到这个歌单**（`SearchViewModel.play()` → `addToDefaultPlaylist()`）
  - 行点击和播放按钮两条路径都走 `play()`，所以都覆盖
  - 重复播放同一首歌不会重复入库
- 用户**不可重命名、不可删除**（Repository 层和 UI 层都拦住了）
- 收藏页歌单卡片上有「默认」标记
- 走的是和其它歌单完全一样的落库链路（`favorites` + `playlist_items`），
  所以这些歌也能被打标签、也能被其它歌单引用

数据层改动：
- `PlaylistEntity` 新增 `isDefault: Boolean`
- Room `version` 1 → 2，AppDatabase 已配 `fallbackToDestructiveMigration()`（旧数据会清空，首版未发布无影响）
- `PlaylistDao` 新增 `getDefault()` / `observeDefaultId()` / `favoriteIdInPlaylistByKey()`

## 5. 顺手修的 bug：专辑封面加载不出来

**现象**：APP 里所有专辑封面都是灰色渐变占位图，一张真封面都看不到。

**根因**：服务端返回的封面地址是 `http://p3.music.126.net/...`，
而本 APP 的 `android:usesCleartextTraffic="false"` 会拦掉所有明文请求，Coil 直接拿不到图。

**修法**：`SafeUrl.upgradeToHttps()` 把 `http://` 升成 `https://`
（网易云图床同时支持 https，实测 200），在 `CoverImage` 里统一处理。

**注意**：MusicFree 插件里也踩了同一个坑，所以插件里对 `artwork` 做了同样的处理。

# B 线：MusicFree 音源插件

完整说明见 **`B1-MusicFree插件使用说明.md`**。这里只列要点。

## 是什么

`moresound.js`（单文件，24 KB）—— 把 `m.resound.vip` 接进 MusicFree，让它变成一个「平台」。

```
MusicFree 官方 APK  +  moresound.js  =  一个能用的网易云替代客户端
```

- **零逆向、零签名、零编译**
- 音乐自控：搜索 / 播放 / 歌词 / 歌手页 / 排行榜 / 歌单广场全走你的源站
- 音源站地址可在插件设置里改，不用改代码

## 为什么是 MusicFree 而不是 LX Music

我把 `lx-music-mobile` 整个源码拉下来读了，**移动版 LX 的自定义源插件协议只有三个动作**：

```ts
// lx-music-mobile/src/types/user_api.d.ts
type UserApiSourceInfoActions = 'musicUrl' | 'lyric' | 'pic'
```

**没有 `search`**。移动版的搜索走的是完全独立的内置链路：

```js
// lx-music-mobile/src/utils/musicSdk/index.js
export const searchMusic = async ({ name, singer, source: s, limit = 25 }) => {
  for (const source of sources.sources) {   // ← 只有 kw/kg/tx/wy/mg/xm，没有 user_api
    tasks.push(sources[source.id].musicSearch.search(...))
```

也就是说：**移动版 LX 的自定义源只能替换「取流」，搜索永远打网易云/QQ/酷狗的官方接口**，
跟你的源是两套完全不同的 id 体系，搜索这一环就断了。
（桌面版 lx-music-desktop 的协议是完整的、含 search，但那是 Electron 桌面软件，不是安卓 APP。）

MusicFree 的 `IPluginDefine` 则是完整的：`search` / `getMediaSource` / `getLyric` /
`getArtistWorks` / `getTopLists` / `getTopListDetail` / `getRecommendSheetTags` /
`getRecommendSheetsByTag` / `getMusicSheetInfo` / `getAlbumInfo` / `importMusicSheet`，
而且 `platform` 是自由字符串，不限内置平台。

## 插件实现的 12 个方法

| 插件方法 | 对应源站接口 | 实现方式 |
|---|---|---|
| `search(query, page, type)` | `/api/search` | 6 渠道并发 + 去重合并，15 条/渠道 |
| `getMediaSource(item, quality)` | `/api/url` | 按 quality 降级链选档位，覆盖 `extra.selectedLevel` |
| `getLyric(item)` | `/api/lyric` | `lines[{time,text}]` → 标准 LRC |
| `getMusicInfo(base)` | — | 会话内缓存反查 |
| `getArtistWorks(artist, page, type)` | `/api/search` | 按歌手名检索 |
| `getTopLists()` | — | 6 个静态榜单预设 |
| `getTopListDetail(item, page)` | `/api/search` | 按榜单关键词检索 |
| `getRecommendSheetTags()` | — | 13 个分类预设 |
| `getRecommendSheetsByTag(tag, page)` | `/api/search` | 按分类关键词检索 |
| `getMusicSheetInfo(item, page)` | `/api/search` | 按歌单关键词检索 |
| `getAlbumInfo(item, page)` | `/api/search` | 按专辑名检索 |
| `importMusicSheet(url)` | `/api/search` | 解析链接里的 id/provider |

两个关键设计：

1. **`cacheControl: 'no-cache'`** —— `/api/url` 的直链约 30 分钟过期。
   MusicFree 在 `no-cache` 模式下只有离线才用缓存，**联网播放每次都会重新调 `getMediaSource`**，
   所以直链过期问题天然不存在。改成 `cache` 反而会在半小时后开始播放失败。
2. **extra 原样透传** —— 服务端靠 `extra.selectedLevel` 决定音质，
   插件任何地方都不改写 extra 的原有字段，只在取流时覆盖 `selectedLevel`。

# 两条线怎么选

| | A 线（自研 APP） | B 线（MusicFree + 插件） |
|---|---|---|
| 包名 | `com.coco.music`，你自己的 | `maotoumao` 的（要自己的包名得 fork MusicFree 重编） |
| UI | 本项目定制的 Material 3 深色 | 网易云级现成 UI |
| 数据完全自控 | ✅ Room 本地库，导出 JSON 备份 | ❌ 走 MusicFree 自己的库 |
| 默认收藏 / 标签 / 歌单 | ✅ 自研实现 | MusicFree 自带（不含你 A 线的新增逻辑） |
| 分类 | ✅ 13 个分类 + 关键词轮换 | ✅ 13 个分类（插件里同一套预设） |
| 歌手可点 | ✅ | ✅（插件 getArtistWorks） |
| 封面/歌词分页 | ✅ | MusicFree 自带交互 |
| 升级维护 | 自己写 | 上游更新 |
| 逆向 / 签名风险 | 无 | 无 |

**建议**：两条一起用。B 线给你现成的网易云级 UI 快速验证体验，
A 线给你数据完全自控 + 自己包名的长期方案。两者共用同一个源站，互不影响。

# 已知限制

1. **分类/榜单/歌单广场是关键词聚合**，不是官方榜单（源没有这些接口）
2. **渠道可用性随关键词变化**：
   - 搜索 + 取流全通：`netease`、`bodian`、`qqmp3`、`mitu`、`migu`
   - 能搜、取流 500：`qq`、`kugou`、`livepoo`、`gequbao`
   - 搜不到 / 超时：`gequhai`、`bugu`、`joox`、`aiting`、`jianbin-*`
3. **未知渠道静默回落**：服务端对没注册的 provider 回落到 netease，APP 会打「已回落」徽标
4. **Room schema 升到 v2**，旧数据会被清空（首版未发布，无影响）

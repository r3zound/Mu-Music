## 2. 服务器地址默认为空，必须手动填写

**APP 不再内置任何地址。**

- `SettingsStore.baseUrl` 默认值从 `https://m.resound.vip` 改成 `""`
- 删除 `SettingsStore.DEFAULT_BASE_URL` 常量
- 写死的地址全部清掉：插件默认值、UI placeholder、文档示例

### 没填地址时会怎样

1. **首页顶部出现引导卡片**「还没有配置音源站地址 / 点这里填写服务器地址后才能开始搜索」，点一下直达设置页
2. **设置页「服务器地址」显示红色的「未设置」**，一眼能看出没配
3. **真去搜索时**，每个渠道返回明确错误：`未设置音源站地址，请到「设置 → 服务器地址」填写`（不再是莫名其妙的 `IllegalArgumentException`）
4. 地址写错（比如不是合法 URL）会提示 `音源站地址不合法：xxx`

实现上在 `MusicApi` 加了统一的 `requireBase()`，4 处 `toHttpUrl()` 全部走它，
所以搜索 / 取流 / 歌词 / 下载四条链路的行为一致。

## 3. 深色主题失效

**根因**：`SettingsStore.themeMode` 存了、设置页也显示了，但 **`MuMusicTheme` 从来没收到这个值**——
`MainActivity` 里写的是 `MuMusicTheme { ... }`，走的是默认参数 `darkTheme = isSystemInDarkTheme()`，
所以你在设置里选「深色」，系统是浅色时依然显示浅色。

**修法**：把主题模式提升到 `MainActivity` 这一层，按设置决定明暗：

```kotlin
val themeMode by settingsStore.themeMode.collectAsStateWithLifecycle(initialValue = ThemeMode.SYSTEM)
val dark = when (themeMode) {
    ThemeMode.SYSTEM -> isSystemInDarkTheme()
    ThemeMode.LIGHT -> false
    ThemeMode.DARK -> true
}
MuMusicTheme(darkTheme = dark) { ... }
```

三种模式现在都真正生效：跟随系统 / 浅色 / 深色。
状态栏图标颜色也跟着走（`isAppearanceLightStatusBars`）。

## 5. 收藏按钮没生效 / 没加进默认收藏

**根因找到了。** 收藏按钮走的是 `toggleFavorite()`，它只往 `favorites` 表插一条记录：

```kotlin
if (ids.isEmpty()) {
    favoriteRepository.addFavorite(item)   // ← 只写 favorites 表！
} else {
    favoriteRepository.removeFavorite(ids.first())
}
```

而 `addFavorite()` **不会**往「默认收藏」歌单加。
结果：歌只出现在收藏页的「全部歌曲」里，**「默认收藏」歌单是空的** —— 也就是你要的那个收藏夹里什么都没有。

更绕的是：点播放时会自动入库到「默认收藏」，而入库链路内部会顺手 `addFavorite()`，
于是收藏按钮会提前变成「已收藏」状态。这时候你再点收藏按钮，它执行的是「取消收藏」，
把歌从默认收藏里踢出去——看起来就像「收藏按钮坏了」。

**修法**：把收藏语义收敛到 Repository 的一个方法里，APP 和插件行为一致：

```kotlin
/**
 * 设置收藏状态。
 * 收藏时除了写 favorites 表，还会把歌加入内置的「默认收藏」歌单。
 */
suspend fun setFavorite(item: MusicItem, favorited: Boolean): Boolean {
    if (favorited) {
        addFavorite(item)
        addToDefaultPlaylist(item)   // ← 补上这一步
        return true
    }
    val id = favoriteIds(item).firstOrNull() ?: return false
    removeFavorite(id)
    return false
}
```

- `SearchViewModel.toggleFavorite()` 和 `PlayerViewModel.toggleFavorite()` 都改成走它
- 搜索结果页点收藏 → 歌进「默认收藏」✓
- 播放页点收藏 → 同样进「默认收藏」，提示文案改成「已收藏到默认收藏」✓
- 取消收藏 → 从所有歌单移除并清掉标签（保持原有语义）

## 7. 顶栏侵入系统通知栏

**根因**：Activity 开了 `enableEdgeToEdge()`（边到边显示），但 `Scaffold` 的内容区只避让了**底部**
（`padding.calculateBottomPadding()`），**没有避让顶部**，所以各页的标题栏直接画进了状态栏区域。

只有播放页自己加了 `statusBarsPadding()`，其余页面全都没有。

**修法**：在 `MainActivity` 的 Scaffold 内容容器统一加 `statusBarsPadding()`，
并把各页面里各自为政的 `statusBarsPadding()` 全部去掉，避免双重避让：

| 文件 | 改动 |
|---|---|
| `MainActivity.kt` | Scaffold 内容加 `.statusBarsPadding()` ← 统一入口 |
| `PlayerScreen.kt` | 去掉自己的 `statusBarsPadding()` |
| `QueueScreen.kt` | 去掉自己的 `statusBarsPadding()` |
| `ChannelHealthScreen.kt` | 去掉自己的 `statusBarsPadding()` |
| `SettingsScreen.kt` | 去掉滚动内容里的 `Spacer(statusBarsPadding())` |

现在首页 / 搜索 / 收藏 / 下载 / 设置 / 播放页 / 队列页 / 渠道体检页
**全部在状态栏下方**，底部导航栏也照旧避让手势区。
